Dialogflow ES ZIP Import and Restore Guide

Practical guide to importing and restoring a Dialogflow ES agent from a ZIP file. Learn the ZIP structure, required filenames, UUIDs, JSON pitfalls, IAM permissions, project problems and the most common import errors.

This guide was built from 3 days of real troubleshooting during the CostyCNC chatbot project. The examples document problems encountered while creating and testing the agent manually.

Why this guide exists

Google's official Dialogflow ES documentation explains how to export, import and restore agents, but it does not cover many of the practical problems you can meet when you manually create or repair the JSON files inside a ZIP. Import errors can be surprisingly cryptic, especially when filenames, IDs, ZIP layout or Google Cloud permissions are involved.

This guide focuses on those practical problems. When possible, compare your manually generated archive with a known-good ZIP exported directly from Dialogflow ES.

What you will find here

  • The exact format of the importable ZIP
  • 10 common problems with tested solutions
  • A Python script that generates the ZIP automatically
  • A ready example chatbot (CostyCNC) to start from
  • A step-by-step tutorial for beginners

Quick Start

Important: Dialogflow ES provides two different ZIP operations. Restore from ZIP overwrites the current agent, while Import from ZIP adds intents and entities and replaces existing ones with the same names. Choose the operation deliberately.

1. Generate the ZIP

python crea_bot.py

Output: dialogflow-es-chatbot.zip

2. Import into Dialogflow ES

  1. Open dialogflow.cloud.google.com
  2. Open Settings → Export and Import
  3. Choose RESTORE FROM ZIP if you intend to replace the current agent
  4. Upload the ZIP file
  5. Type IMPORT to confirm the restore

If you see "Agent import successful" in green → DONE!

3. Test the bot

In the right panel "Try it now":

hello
how do I convert svg to gcode
how much does it cost

Problem 1: 'X' is not a valid intent ID. Must be a UUID EASY

Validate intent with display name 'goodbye' failed because of the following reasons: 'intent-017' is not a valid intent ID. Must be a UUID.

Cause

If you are generating the exported JSON format manually, an ID such as intent-001 is not a valid UUID. Use a valid UUID value for the ID fields required by the format.

Solution

Replace:

"id": f"intent-{counter:03d}",   # WRONG

with:

import uuid
"id": str(uuid.uuid4()),         # CORRECT
Every id (intent, training phrase, response) must be generated with str(uuid.uuid4()).

Problem 2: can not be passed into JsonElement MEDIUM

This file 'intents/image_to_gcode_user_says.json' can not be passed into JsonElement. Check if this is in valid json format.

Cause

The training-phrase filename does not match the exported Dialogflow ES naming convention used by this example agent.

WRONG names

FilenameWhy it's wrong
image_to_gcode_user_says.json"user_says" (singular, no "it")
image_to_gcode_usersays.jsonMissing "_it" suffix
image_to_gcode_user_says_it.json"user_says" instead of "usersays"

CORRECT name

{intent_name}_usersays_it.json
Must be all attached: usersays (plural, no underscore) + _it (language).

Problem 3: BadRequestException during import MEDIUM

com.google.apps.framework.request.BadRequestException

Possible causes

  • UTF-8 BOM at the beginning of the file (invisible character)
  • Apostrophes not properly handled
  • Emoji in texts
  • JSON with double commas or unbalanced brackets
  • Agent ZIP exceeds Google's current maximum of 50 MB uncompressed

Solution

  1. Open the file with Notepad++
  2. Menu Encoding → UTF-8 (NOT "UTF-8 BOM")
  3. Save
  4. Validate JSON at jsonlint.com
Always save files as UTF-8 without BOM.

Problem 4: Nothing to import EASY

Causes

  • Nested folder inside the ZIP (e.g. costycnc-bot/costycnc-bot/)
  • Missing agent.json in the root
  • Missing intents/ folder

Correct structure

dialogflow-es-chatbot.zip
+-- costycnc-bot/         <- ONLY ONE folder
    +-- agent.json
    +-- package.json
    +-- intents/
        +-- greeting.json
        +-- greeting_usersays_it.json

WRONG structure

dialogflow-es-chatbot.zip
+-- costycnc-bot/
    +-- costycnc-bot/     <- NESTED!
        +-- agent.json
        +-- intents/
Zip the folder, not its content. The result must have agent.json in a subfolder, not in the ZIP root.

Problem 5: Permission 'dialogflow.agents.get' not granted HARD

com.google.apps.framework.auth.IamPermissionDeniedException: Permission 'dialogflow.agents.get' not granted to cloud-ml-dialogflow-frontend@prod.google.com, because no ALLOW or ALLOW_WITH_LOG rule includes that permission.

Cause

You are trying to enable an integration (e.g. Dialogflow Messenger) but your account does not have the necessary IAM permissions on the Google Cloud project.

OR you are working in the WRONG Google Cloud project! This is the most common cause.

Step-by-step solution

Step 1 - Find the correct Project ID:
Dialogflow → Settings → General → copy the Project ID

Step 2 - Go to Google Cloud Console

Step 3 - Top left, click the project name and select the correct project.
If it does not appear → see Problem 8

Step 4 - Menu → IAM & Admin → IAM

Step 5 - Find your email address in the list → click the pencil icon

Step 6 - Add roles:

  • Dialogflow API Admin (when API-level access is required)
  • Dialogflow Console Agent Editor (for editing the agent)

Step 7 - SAVE → back to Dialogflow → reload → retry

After adding IAM permissions, the ENABLE button becomes clickable.

Problem 6: Old URL console.dialogflow.com/api-client/demo/embedded no longer works EASY

The web page at https://console.dialogflow.com/api-client/demo/embedded/... might be temporarily down or it may have moved permanently to a new web address.

Cause

The old embedded Web Demo URL may no longer match the current console or integration workflow. Use the integration currently provided by Dialogflow ES and verify the current options in the console.

Current alternative: Dialogflow Messenger

Step 1 - Dialogflow → Integrations → Dialogflow Messenger

Step 2 - Click ENABLE (if error → Problem 5)

Step 3 - Copy the generated code:

<script src="https://www.gstatic.com/dialogflow-console/fast/messenger/bootstrap.js?v=1"></script>
<df-messenger
  intent="WELCOME"
  chat-title="CostyCNC"
  agent-id="YOUR_AGENT_ID"
  language-code="en">
</df-messenger>
Do NOT confuse agent-id with Project ID!
- agent-id = UUID like 9378968c-5941-48e8-95e1-8014f7fa02f5
- Project ID = string like costycnc-bot-lxxc

Problem 7: Bot always replies with Fallback MEDIUM

Possible causes

  • Training phrases not imported
  • Classification threshold is too high for the phrases being tested
  • The agent needs to retrain after changes

Solution

  1. Verify training phrases: open the intent → check the phrases
  2. Click SAVE in the intent → forces retraining
  3. Wait for training to complete
  4. Retry
  5. If still failing → lower ML threshold:

If the intent still falls back, inspect ML Settings and the Classification threshold. A lower threshold can make matching more permissive, but test carefully because it can also increase false matches.

Problem 8: Google Cloud project not showing in the list HARD

Symptom

In the "Select a project" screen I cannot see the costycnc-bot project.

Possible causes

  1. Logged in with a different Google account
  2. Project in a corporate organization not accessible
  3. The agent is associated with a different or inaccessible Google Cloud project
  4. Project name is completely different (e.g. "My First Project")

Solution

Check 1 - Verify the account is the same in Dialogflow and Cloud Console

Check 2 - Find the real Project ID: Dialogflow → Settings → General

Check 3 - Search by ID in the "Select project" screen

If the project really exists, it will appear when searching by ID even if the name is different.
If it does not appear, the agent is probably a temporary trial → you need to create a new agent in a real Cloud project.

Alternative - Create a new project

  1. Go to Google Cloud Console
  2. Top → Select a project → NEW PROJECT
  3. Name: costycnc-chatbot
  4. Create
  5. Back to Dialogflow → create a new agent selecting this project
  6. Reimport the ZIP

Problem 9: Nested folder inside the ZIP EASY

Cause

Your ZIP creation script placed the generated agent inside an unnecessary wrapper folder. This can produce an archive such as costycnc-bot/agent.json instead of putting agent.json at the ZIP root.

Solution

# WRONG: run inside costycnc-bot/
cd costycnc-bot/
python crea_bot.py
# -> creates costycnc-bot/costycnc-bot/

# CORRECT: run from a neutral folder
cd /Desktop/work/
python crea_bot.py
# -> creates work/costycnc-bot/
Always run the script from a neutral folder that is not named like the agent.

Problem 10: IMPORT button grey/disabled EASY

Cause

In the current restore/import confirmation flow, the action may remain disabled until the required confirmation text is entered.

Solution

  1. In the text field type: IMPORT (all caps)
  2. The IMPORT button becomes blue/clickable
  3. Click it
Type exactly IMPORT - no spaces, no lowercase.

Extra Tips (from field experience)

These tips are additional to the 10 problems above. The guide works perfectly without them, but they can save you extra time.

1. Language suffix must match your agent

The guide uses _it because the example agent is in Italian. If your agent is in English, the files must be named {name}_usersays_en.json. The suffix is the language code of the agent, not a fixed value.

Always check the agent language in Settings → General before generating the ZIP.

2. Keep a "known good" ZIP as reference

Before modifying the Python script or the JSON files, export a working agent from Dialogflow (Settings → Export and Import → EXPORT AS ZIP). That ZIP is the official reference format.

Compare your generated ZIP with the exported one. The structure must be identical. This is the fastest way to spot naming or field differences.

3. UUIDs must be unique, not just valid

A common mistake is to generate one UUID and reuse it everywhere. Dialogflow accepts it during import but the agent will behave unpredictably.

Every id field must come from a separate str(uuid.uuid4()) call. Never reuse.

4. IAM roles: prefer least privilege

The guide suggests adding Editor (generic) to fix Problem 5. It works, but it is broader than needed.

For a cleaner setup, use only: Dialogflow API Admin + Dialogflow Console Agent Editor. Add Editor only if strictly necessary.

5. Test the import on a throwaway agent first

Restore from ZIP overwrites the current agent. By contrast, Import from ZIP adds intents and entities and replaces ones with the same names.

Create a temporary empty agent, import there first, verify everything works, then import into the real agent.

6. The "Last updated" date matters

Dialogflow ES is a mature product but Google still changes IAM behavior, deprecates URLs (see Problem 6) and updates the console UI.

If a step does not match what you see, check the official Dialogflow ES docs for recent changes before assuming the guide is wrong.

7. Watch out for invisible characters in JSON

Problem 3 mentions BOM, but other invisible issues exist: non-breaking spaces (\u00A0), smart quotes (“ ” ‘ ’) copied from Word or web pages, and zero-width spaces.

Always type JSON strings manually or paste through a plain-text editor. Never copy from Word, Google Docs or rendered HTML.
